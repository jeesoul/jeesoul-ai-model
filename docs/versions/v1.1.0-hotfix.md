# v1.1.0 / beta / beta2 补丁方案（已被 beta3 取代，建议直接升级）

> ## 🔴 首选方案：升级到 1.1.0-beta3，不要再打补丁
>
> **1.1.0-beta3 已发布至 Maven 中央仓库。**
> 它从代码层面修掉了根因，只需引入本库一个依赖即可，不再需要本文的任何补丁：
>
> ```xml
> <dependency>
>     <groupId>com.jeesoul</groupId>
>     <artifactId>jeesoul-ai-model</artifactId>
>     <version>1.1.0-beta3</version>
> </dependency>
> ```
>
> **升级时请把本文教你加的三个补丁依赖全部删掉**，留着会把项目钉死在
> `httpclient5:5.2.3`（落在 CVE-2026-64607 影响区间 `>=5.0-alpha1, <5.6.3` 内），
> 并静默顶掉将来 Spring Boot BOM 抬高的版本。详见
> [v1.1.0-beta3 版本说明](v1.1.0-beta3.md)。
>
> 本文以下内容仅保留给**暂时无法改动依赖版本号**的项目应急使用。

⚠️ 1.1.0、1.1.0-beta、1.1.0-beta2 三个版本在 Spring Boot 2.7.x 下运行期均会报错。
本文给出的补丁可让这三个版本临时正常工作。
但它只是权宜之计，能升版本就升 beta3。

## 问题现象

调用大模型时报错：

```
java.lang.NoClassDefFoundError: org/apache/hc/client5/http/config/ConnectionConfig
java.lang.ClassNotFoundException: org.apache.hc.client5.http.config.ConnectionConfig
    at com.jeesoul.ai.model.http.engine.HttpClientEngine.buildClient(HttpClientEngine.java:158)
```

## 根本原因

根因是**库的代码用了太新的 HttpClient5 API**，而不是依赖没传递过去。

`ConnectionConfig` 这个类是 httpclient5 **5.2 才引入**的。1.1.0 系列的 `HttpClientEngine.buildClient()` 用了它，
所以运行时的 httpclient5 只要低于 5.2，就会找不到类。

而使用方拿到的版本为什么会低于 5.2：

1. 使用方继承 `spring-boot-starter-parent:2.7.17`，该 BOM 把 `httpclient5` 管在 **5.1.4**、`httpcore5` 管在 **5.1.5**
2. Maven 规则：**使用方继承的 dependencyManagement 优先级高于传递依赖的版本**
3. 于是本库 pom 里写的 `httpclient5 5.2.3` 传到使用方后，被强制改写成 5.1.4

所以 1.1.0-beta / beta2 只改版本号、不改代码，是无效的 —— 三个依赖在发布的 pom 里一直都在，
被覆盖的是版本，不是依赖本身。

补丁之所以有效，是因为**使用方直接声明的依赖优先级高于继承的 dependencyManagement**，
能把版本重新顶回 5.2.3，让 `ConnectionConfig` 可用。

## 补丁方案

在使用方项目的 `pom.xml` 的 `<dependencies>` 里补上三个依赖（**必须是直接声明，写在 dependencyManagement 里无效**）：

```xml
<dependencies>
    <!-- 原有的 jeesoul-ai-model 依赖，版本不用改 -->
    <dependency>
        <groupId>com.jeesoul</groupId>
        <artifactId>jeesoul-ai-model</artifactId>
        <version>1.1.0</version>
    </dependency>

    <!-- 关键一步：直接声明 httpclient5，顶掉 parent BOM 管理的 5.1.4 -->
    <dependency>
        <groupId>org.apache.httpcomponents.client5</groupId>
        <artifactId>httpclient5</artifactId>
        <version>5.2.3</version>
    </dependency>

    <!-- 配套的 httpcore5，与 httpclient5 5.2.x 匹配 -->
    <dependency>
        <groupId>org.apache.httpcomponents.core5</groupId>
        <artifactId>httpcore5</artifactId>
        <version>5.1.5</version>
    </dependency>
    <dependency>
        <groupId>org.apache.httpcomponents.core5</groupId>
        <artifactId>httpcore5-h2</artifactId>
        <version>5.1.5</version>
    </dependency>
</dependencies>
```

三个都要加。只补 `httpcore5` 不升 `httpclient5`，`ConnectionConfig` 依然找不到。

### 验证环境

补丁已在如下环境实测通过，应用正常启动、大模型调用正常返回：

- Spring Boot 2.7.17（`spring-boot-starter-parent`）
- Java 8
- `jeesoul-ai-model:1.1.0` + 上述三个补丁依赖

### 验证方式

打完补丁后执行下面命令，确认最终仲裁出的版本是 httpclient5 5.2.3：

```bash
mvn dependency:tree -Dincludes=org.apache.httpcomponents.client5:*,org.apache.httpcomponents.core5:*
```

若显示的仍是 5.1.4，说明补丁没生效，检查是否误写进了 `<dependencyManagement>`。

## 后续版本

1.1.0-beta3 起，库内 `HttpClientEngine` 已改为只使用 httpclient5 5.1.x 就存在的 API
（`SocketConfig` + `RequestConfig` + `setConnectionTimeToLive`），不再引用 `ConnectionConfig`。
因此无论使用方的 BOM 把版本管到 5.1.x、5.2.x、5.5.x 还是 5.6.x，都能正常运行，
使用方**不需要再挂这三个补丁依赖**，删掉补丁、只改版本号即可，业务代码无需改动。

beta3 已实测覆盖 httpclient5 5.1.4 / 5.2.3 / 5.5.1 / 5.6.4 四组运行时组合，
并实测 JDK 8 与 JDK 17 运行时均正常，Spring Boot 2.7.x 与 3.x 均可使用。
