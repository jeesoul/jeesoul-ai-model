# v1.1.0 补丁方案（已验证可用）

⚠️ 版本 1.1.0 的 pom 依赖声明有缺陷，直接引入会在运行期报 `ClassNotFoundException`。
本文给出的补丁**已在真实项目中验证通过**，无需等待新版本即可让 1.1.0 正常工作。

## 问题现象

引入 `jeesoul-ai-model:1.1.0` 后，调用大模型时报错：

```
java.lang.ClassNotFoundException: org.apache.hc.client5.http.config.ConnectionConfig
java.lang.ClassNotFoundException: org.apache.hc.core5.http.HttpEntity
java.lang.ClassNotFoundException: org.apache.hc.core5.io.ModalCloseable
```

## 根本原因

1.1.0 的 `pom.xml` 有两处问题：

1. **依赖声明位置错误**：`httpcore5`、`httpcore5-h2` 只写在 `<dependencyManagement>` 里。
   `dependencyManagement` 只管版本、不引入依赖，所以这两个包不会作为传递依赖交付给使用方。
2. **版本组合不匹配**：`httpclient5` 锁的是 5.5.1，它需要配套 `httpcore5` 5.3.x；
   而使用方多为 Spring Boot 2.7.x，其 BOM 把 `httpcore5` 管在 5.1.x，两边对不上。

补齐 `httpcore5` 之后仍然报错，是因为版本线还是错的 —— 光补包不够，必须把 `httpclient5` 拉回与 `httpcore5` 5.1.x 配套的 5.2.3。

## 补丁方案

在使用方项目的 `pom.xml` 里补上三个依赖：**降级 httpclient5 + 补齐 httpcore5**。

```xml
<dependencies>
    <!-- 原有的 jeesoul-ai-model 依赖，版本不用改 -->
    <dependency>
        <groupId>com.jeesoul</groupId>
        <artifactId>jeesoul-ai-model</artifactId>
        <version>1.1.0</version>
    </dependency>

    <!-- 关键一步：降级 httpclient5，覆盖 1.1.0 传递过来的 5.5.1 -->
    <dependency>
        <groupId>org.apache.httpcomponents.client5</groupId>
        <artifactId>httpclient5</artifactId>
        <version>5.2.3</version>
    </dependency>

    <!-- 补齐 1.1.0 未传递的 httpcore5 -->
    <dependency>
        <groupId>org.apache.httpcomponents.core5</groupId>
        <artifactId>httpcore5</artifactId>
        <version>5.1.5</version>
    </dependency>
    <dependency>
        <groupId>org.apache.httpcomponents.core5</groupId>
        <artifactId>httpcore5-h2</artifactId>
        <version>5.1.5</version>
    </dependency>
</dependencies>
```

三个都要加，缺一个都不行：只补 `httpcore5` 会继续报 `ConnectionConfig` 找不到，只降 `httpclient5` 会报 `HttpEntity` 找不到。

### 验证环境

补丁已在如下环境实测通过，应用正常启动、大模型调用正常返回：

- Spring Boot 2.7.17（`spring-boot-starter-parent`）
- Java 8
- `jeesoul-ai-model:1.1.0` + 上述三个补丁依赖

### 验证方式

打完补丁后执行下面命令，确认最终仲裁出的版本是 httpclient5 5.2.3、httpcore5 5.1.5：

```bash
mvn dependency:tree -Dincludes=org.apache.httpcomponents.client5:*,org.apache.httpcomponents.core5:*
```

## 后续版本

补丁是把修复责任放在使用方 pom 里，属于权宜之计。后续版本会在组件自身的 `<dependencies>` 中显式声明完整依赖，
使用方只改一个版本号即可，不用再挂这三个补丁依赖。届时删掉补丁、升级版本号即可，业务代码无需改动。
