# v1.1.0-beta3 版本说明

## 版本定位

**真正修复 HttpClient5 兼容性问题的版本。**

1.1.0、1.1.0-beta、1.1.0-beta2 三个版本在 Spring Boot 2.7.x 下都会在运行期抛
`NoClassDefFoundError: org/apache/hc/client5/http/config/ConnectionConfig`。
前两次 beta 只改了 pom 的依赖版本、没改代码，因此没能解决问题。beta3 从代码层面修掉了根因。

## 根本原因（前两次 beta 修错了方向）

之前判断为「发布时遗漏依赖声明」，这个判断是错的。发布到中央仓库的 pom 里，
`httpclient5` / `httpcore5` / `httpcore5-h2` 三个依赖一直都在。

真正的原因是**库代码用了太新的 API**：

1. `ConnectionConfig` 是 httpclient5 **5.2 才引入**的类，`HttpClientEngine.buildClient()` 用了它
2. 使用方继承 `spring-boot-starter-parent:2.7.17`，其 BOM 把 `httpclient5` 管在 **5.1.4**
3. Maven 规则：**使用方继承的 dependencyManagement 优先级高于传递依赖的版本**，
   本库声明的 5.2.3 传过去后被强制改写为 5.1.4
4. 5.1.4 里没有 `ConnectionConfig` → 运行期找不到类

结论：只要库代码依赖 5.2+ 的 API，任何改版本号的做法都救不了使用方，
因为版本的最终仲裁权在使用方的 BOM 手里，不在本库。

## 本次修复

### 代码：只使用全版本区间共有的 API

`HttpClientEngine.buildClient()` 移除 `ConnectionConfig`，改用 5.1.x 就存在的等价 API：

| 原写法（5.2+ 才有）                        | 新写法（5.1.x ~ 5.5.x 通用）                              |
|---------------------------------------|---------------------------------------------------|
| `ConnectionConfig.setSocketTimeout`   | `SocketConfig.setSoTimeout`（连接管理器 defaultSocketConfig） |
| `ConnectionConfig.setConnectTimeout`  | `RequestConfig.setConnectTimeout`                 |
| `ConnectionConfig.setTimeToLive`      | `PoolingHttpClientConnectionManagerBuilder.setConnectionTimeToLive` |

`RequestConfig.setConnectTimeout` 在 5.2 后被标记废弃但始终保留，是 5.1.x 与 5.2+ 唯一共有的连接超时入口，请勿改回 `ConnectionConfig`。

### pom：按最低支持版本编译

`httpclient5` 声明版本从 5.2.3 下调为 **5.1.4**、`httpcore5` 为 **5.1.5**，与 Spring Boot 2.7.x BOM 完全对齐。
这样做的目的不是「降级」，而是让本库**按支持的最低版本编译**——
一旦后续有人误用 5.2+ 的新 API，会在本项目编译期直接报错，而不是等使用方在生产环境炸。

版本号已抽为 `httpclient5.version` / `httpcore5.version` 属性，便于跨版本回归验证。

使用方若需要更高版本，在自己 pom 里直接声明覆盖即可，本库代码在 5.1.x ~ 5.5.x 全区间可运行。
Spring Boot 3.x 使用方会由其 BOM 自动抬到 5.2/5.3，同样正常。

## 兼容性验证

已实测三组运行时组合，均能正常构建 HTTP 客户端（编译 + 运行双重验证）：

| httpclient5 | httpcore5 | 编译 | 运行 |
|-------------|-----------|------|------|
| 5.1.4       | 5.1.5     | 通过 | 通过 |
| 5.2.3       | 5.2.4     | 通过 | 通过 |
| 5.5.1       | 5.3.6     | 通过 | 通过 |

同时确认编译产物字节码中已无任何 `ConnectionConfig` 引用。

## 升级方式

### 从 1.1.0 / 1.1.0-beta / 1.1.0-beta2 升级

改版本号，并**删掉之前加的补丁依赖**：

```xml
<dependency>
    <groupId>com.jeesoul</groupId>
    <artifactId>jeesoul-ai-model</artifactId>
    <version>1.1.0-beta3</version>
</dependency>
```

之前为绕过问题手工加的 `httpclient5` / `httpcore5` / `httpcore5-h2` 三个依赖可以全部删除，
beta3 不再需要它们。留着也不影响，但没有必要。

执行 `mvn clean install -U` 强制刷新依赖。

### 业务代码

无需任何改动。公共 API 与历史版本完全一致，本次只换内部实现。

## 已知遗留

1.1.0、1.1.0-beta、1.1.0-beta2 已发布到中央仓库且不可撤回，仍在使用这三个版本的用户，
可参考 [v1.1.0 补丁方案](v1.1.0-hotfix.md) 临时绕过，或直接升级到 beta3。
